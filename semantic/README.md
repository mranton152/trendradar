# Семантика: K-04–K-08

Код работает с неизменными WORKS / CANDIDATES / CAND_DOCS из contracts/.
Модель `intfloat/multilingual-e5-large` закреплена на ревизии
`3d7cfbdacd47fdda877c5cd8a79fbcc4f2a574f3`.

## Запуск

Из корня репозитория, с зависимостями pyproject.toml и ML extra:

```powershell
python -m semantic.build --domain artificial-intelligence --works data/index/golden/works.parquet --scope sample --as-of 2026 --output data/index/ai-smoke --cache data/cache/embeddings --model-cache data/cache/models
```

Для корпусного результата используйте `--scope full` и works.parquet из
завершённого ingest.full. SHA-256, n_works, домен и год manifest должны совпадать.
Входной срез не объявляется полным корпусом вручную одной сменой флага.

Каталог --output должен быть новым: публикация атомарно переименовывает
подготовленный каталог и не перезаписывает существующий индекс.
`--terms-only` создаёт только кандидатов-термины; это явно указано в meta.json.
Для полного режима по умолчанию используется CUDA. CPU нужно выбрать явно
`--device cpu`; он пригоден для небольших диагностических прогонов.

## Что сохраняется

- `candidates.parquet`, `cand_docs.parquet`: реальные кандидаты и их doc_id.
- `embeddings.npy`: float32 `(N_clusters, 1024)`, нормированные центроиды.
  `emb_row` индексирует только эти строки; у терминов `emb_row=null`.
- `works.parquet`: исходный корпус рядом с индексом для офлайн-потребителей.
- `meta.json`: хэш корпуса, охват sample/full, статистика, версии библиотек,
  скорость кодирования и сравнение кластеризации для размеров10/25/50.

В --cache отдельно лежат **документные** `document_embeddings.npy`, checkpoint
с порядком doc_id и `reduced.npy`. Документный массив не выдаётся за контрактный
массив кандидатов. После прерывания уже закодированные батчи не пересчитываются.
При изменении корпуса или модели кэш отклоняется.

## Алгоритм

E5 кодирует `passage: title. abstract`, максимум512 токенов. Выход нормируется;
при CUDA OOM размер батча уменьшается, модель не меняется. Начальный batch64.
UMAP:15 соседей,5 измерений, min_dist0, cosine, seed42. HDBSCAN: min_samples5,
euclidean, eom; основной min_cluster_size25. Шум -1 в кластеры не включается.

c-TF-IDF соответствует BERTopic: L1-нормированная частота класса умножается
на `log(1 + A / frequency)`, где A — средняя длина класса, frequency — суммарная
частота слова по классам. Название — первые4 слова, top_terms — первые10.
Источник формулы: https://maartengr.github.io/BERTopic/getting_started/ctfidf/ctfidf.html
Требования e5: https://huggingface.co/intfloat/multilingual-e5-large

Термины: смежные2–4-граммы заголовков, каждый документ учитывается один раз,
минимум20 документов (`--min-docs`). Фильтр лексический: технологические маркеры,
события/болезни/организации и проверка некоторых конечных модификаторов.
Это не полноценный POS-теггер и не доказательство технологичности. Кластеры
проверяются по исходным заголовкам, чтобы не потерять многословные технологии.
Редкие технологии без словарных маркеров могут быть отвергнуты; причины сохранены.

## Ограничения масштаба

Документные векторы записываются через memmap, однако тексты, словарь терминов,
список связей и граф UMAP на этом этапе находятся в памяти. По умолчанию CLI
отклоняет корпуса больше200000 строк; увеличивать --max-documents следует только
после оценки RAM. Полные6,3млн документов ИИ требуют отдельного решения по памяти
и времени; проверочный прогон на5тыс. не доказывает масштабируемость на6млн.

Воспроизводимость чисел предполагает те же версии библиотек/устройство; seed42
не обещает побайтового равенства CPU и GPU. В meta.json записываются версии.
Нельзя считать термины из небольшого равномерного среза доказанными слабыми сигналами.

## Проверки

```powershell
python -m pytest ingest semantic -q
python -m ruff check ingest semantic
python -X utf8 contracts/validate.py data/index/ai-smoke/candidates.parquet --schema candidates
python -X utf8 contracts/validate.py data/index/ai-smoke/cand_docs.parquet --schema cand_docs
```

Для другого домена используются те же команды и его works.parquet.
Для OpenAlex quantum-computing задавайте проверенный концепт C58053490
(название каталога OpenAlex — Quantum computer). Биотехнологии — C150903083.
