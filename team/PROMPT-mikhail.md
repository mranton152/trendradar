## Что изменилось после ТЗ

Интерфейс теперь описан заказчиком в деталях, и жюри будет проверять по списку.
Плюс появился **живой режим**: жюри вводит произвольное направление, система
собирает источники и считает выдачу за минуты. Нужен экран ожидания с прогрессом.

**Твои папки: `cards/`, `api/`, `web/`.**

## Задачи, по порядку

### M-09. Карточка источника по ТЗ (дни 1–2)
Для каждого источника показывать: **наименование, ссылку, дату публикации, тип
источника, язык оригинала, уровень доверенности**. Поля уже в контракте `WORKS`:
`date`, `source_type`, `lang`, `trust_level`. Уровень — цветной бейдж:
`trusted` / `indicator` («только индикатор») / `unknown`. Для `indicator`
подпись: «не может быть единственным основанием».

### M-10. Русское резюме зарубежного источника (дни 2–3)
Поле `summary_ru` в `WORKS`, генерируется в `cards/build.py` той же моделью,
что и карточки. Обязательно рядом с резюме пометка **«резюме сгенерировано,
модель: …»** — ТЗ требует явно. Оригинальное название, ссылка, дата и язык
остаются как есть. Генерировать только для `top_doc_ids`, не для всего корпуса.

### M-11. Отсеянные кандидаты с причинами (день 3)
Антон пишет `data/index/{domain}/rejected.parquet` (`cand_id`, `label`,
`reason`, `n_docs`). Показать под списком ТОП-15 раскрывающийся блок
«Исключено: N кандидатов» с таблицей причин. Это прямое требование ТЗ —
«причины исключения зрелых технологий» — и наш сильный аргумент: `lynching tree`
с нулём стран должен быть виден.

### M-12. Счётчики в шапке (день 4)
Как на макете в ТЗ: **обработано источников**, **найдено кандидатов**,
**сигналов с уверенностью >75%**. Данные из `meta.json` и `trends.parquet`.
Уверенность — `emergence_score` в процентах, «ES 0.702» → «70%».

### M-13. Живой режим с прогрессом (дни 4–7) — главная задача
Домена нет в индексе → `POST /api/v1/live` запускает `ingest.live` + `core.build`
как фоновую задачу (subprocess, без очередей), возвращает `job_id`.
`GET /api/v1/live/{job_id}` — стадия и счётчики. Фронт показывает экран
«Собираем источники… 214 документов · Ищем кандидатов… · Считаем» и по
готовности переходит к выдаче. Готовый результат кэшируется в `data/index/`
как обычный домен. **Это то, что жюри увидит первым.**

### M-14. Docker и стенд (дни 7–9)
`docker compose up` поднимает `api`, `web`, `postgres` (Антон даёт схему).
arm64 обязателен. README с командами. Стенд — на Yandex Cloud по гранту
SourceCraft, Антон принесёт доступ; до этого — на своём ноуте через туннель.

### M-15. Экспорт XLSX (день 10)
ТОП-15 со всеми полями и источниками. Аналитики банка живут в Excel.
