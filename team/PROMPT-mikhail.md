## Твоя зона

Ты делаешь **всё, что видит жюри**. Данные и метрики считают Константин и Антон,
их результат приходит к тебе готовыми файлами. Твоя работа — превратить эти файлы
в сервис, который открывается, работает быстро и убедительно выглядит на защите.

**Твои папки: `cards/`, `api/`, `web/`. Больше никуда не пишешь.**

Важно: **API ничего не считает.** Он читает `data/index/{domain}/trends.parquet` и
`cards.parquet` и отдаёт JSON. Никаких обращений к внешним источникам в рантайме —
демо обязано работать в самолётном режиме.

## Что ты получаешь на вход

| Файл | От кого | Схема |
|---|---|---|
| `data/index/{domain}/trends.parquet` | Антон | `contracts/schemas.py` → `TRENDS` |
| `data/index/{domain}/cand_docs.parquet` | Константин | → `CAND_DOCS` |
| `data/corpus/{domain}/works.parquet` | Константин | → `WORKS` |

Пока их нет — работаешь на `data/index/golden/`, это настоящий мини-срез,
он появится в первый же день.

## Задачи Фазы 0 (08.09 — 14.09), по порядку

### M-01. Каркас API (день 1)
```
api/
  main.py        FastAPI, CORS, /health
  store.py       чтение parquet через DuckDB, кэш в памяти
  models.py      Pydantic-схемы ответа, сгенерированы по contracts/api.openapi.yaml
  routes/
    trends.py
    domains.py
    methodology.py
    export.py
```
Требования:
- ответ < 1 секунды (всё в памяти, parquet читается на старте);
- на старте логировать, какие домены нашлись в `data/index/`;
- если индекса нет вообще — отдавать понятную ошибку, а не 500.

Читать parquet проще всего через DuckDB, SQL работает прямо по файлу:
```python
import duckdb
con = duckdb.connect()
rows = con.sql("""
    SELECT * FROM 'data/index/artificial-intelligence/trends.parquet'
    WHERE as_of = 2026 ORDER BY rank LIMIT 15
""").fetchall()
```

### M-04. Генерация карточек, RAG (дни 3–5)
Это единственное место в системе, где работает LLM. Правила жёсткие:

- вход — только `top_doc_ids` тренда из `trends.parquet` (10–20 документов:
  название + абстракт + год + ссылка);
- модель обязана вернуть **строгий JSON** по схеме `CARDS`;
- **каждое утверждение несёт `doc_ids`**;
- на постобработке: утверждение, чьи `doc_ids` пусты или не встречаются во входных
  документах, **выбрасывается**. Не «помечается», а выбрасывается;
- считаем `citation_coverage` — долю утверждений с подтверждённым источником.
  Целимся в 1.0, эту цифру показываем жюри;
- провайдер модели — за абстракцией: `LLM_BACKEND=ollama|openai_compatible|gigachat`.
  В банке внешние API недоступны, это прямо влияет на оценку.

Для разработки: `ollama pull qwen2.5:7b`, на M1 Pro 16 ГБ идёт нормально.
Финальный прогон всех карточек — на машине Константина, там модель побольше.

Промпт модели должен запрещать любые утверждения, не выводимые из поданных
документов. Формулировка примерно такая: «Ты не эксперт по теме. Ты извлекаешь
факты из поданных документов. Если факта в документах нет — не пиши его».

### M-05. Вкладка «Методология» (день 5)
Прямое требование заказчика. На экране: веса компонент, пороги фильтров, из чего
сложился Emergence Score конкретного тренда (столбики по пяти компонентам),
результаты бэктеста. Данные берёшь из `/api/v1/methodology` — их отдаёт Антон.

### M-06. Режим `as_of` в интерфейсе (день 6)
Переключатель года среза. Ставим 2021 — сервис показывает, что он нашёл бы тогда,
и что из этого выросло к 2026. **Это главный номер демо**, ему нужен отдельный,
заметный элемент управления, а не спрятанный в настройках чекбокс.

### M-07. Экспорт XLSX (день 7)
Аналитики банка живут в Excel. Выгрузка ТОП-15 со всеми полями, ссылками и
годовыми рядами. PDF — потом, если останется время.

### M-08. Docker Compose (день 7)
Два сервиса: `api` и `web`. Обязательно arm64-совместимо (у нас два мака).
`docker compose up` должен поднимать всё с нуля на чистой машине — жюри просит.
