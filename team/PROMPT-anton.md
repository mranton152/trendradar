## Задачи, по порядку

### A-09. Контракты под ТЗ (день 1, блокирует всех)
`WORKS` += `source_type` (article|preprint|patent|news|blog|repo|model|report|
aggregator|press_release), `trust_level` (trusted|indicator|unknown),
`summary_ru`, `summary_model` — все nullable, чтобы не ломать golden.
Новая таблица `REJECTED` (`cand_id`, `label`, `reason`, `n_docs`, `as_of`).
`TRENDS` += `bt_at_cutoff`, `bt_peak_after`, `bt_growth_x` — nullable,
заполняются при `as_of` в прошлом. `meta.json` += счётчики. Одним PR, с миграцией
golden. Всем — `git pull`.

### A-10. Отсеянные — в файл (день 1)
`core.build` пишет `rejected.parquet` из счётчика `отказы`. Тест: `lynching tree`
с нулём стран попадает туда с причиной «нет географического распространения».

### A-11. Живой скоринг (дни 2–4)
`core.build --live data/live/{slug}` — вход без `embeddings.npy`, без кластеров,
кандидаты — термины и сущности от Кости. Ряды короткие (24 месяца новостей +
точечный OpenAlex по годам): компоненты считать на **месячных** рядах для
новостей и годовых для публикаций, потом сводить. Peer-нормировка — по пулу
живого корпуса. Критерий: `core.build --live` на 300 документах — ≤10 секунд.

### A-12. Классификатор — этап 1 (дни 3–9) — главная задача
`classifier/`:
- `dataset.py` — 100 положительных из xlsx + отрицательные, которые собираем
  сами: расширить антиэталон до ~100 зрелых технологий, отраслевых стандартов
  и хайпа по тем же шести областям. Каждый отрицательный — с обоснованием,
  почему зрелый, в комментарии. Это станет слайдом.
- `features.py` — наши пять компонент + зрелость + новостные признаки от Кости
  (K-14) + число компаний + доля trusted-источников. Все признаки — с человеческим
  описанием, они пойдут в отчёт как «предикторы».
- `train.py` — логистическая регрессия **и** градиентный бустинг, оба
  интерпретируемы; стратифицированная 5-fold кросс-валидация; отчёт
  P/R/F1/accuracy. Выбрать простейшую модель, проходящую порог.
- `explain.py` — по наблюдению: вклад каждого признака (коэффициенты или SHAP).
  Это и есть «система обязана показывать, по каким признакам».
- `REPORT.md` — метрики, матрица ошибок, важность признаков, что не сработало.
Критерий: accuracy ≥80% на кросс-валидации, и каждый признак объясним фразой.
Честность: если порог не берётся — отчёт говорит почему, а не подкручивает.

### A-13. Postgres как хранилище (день 10)
`storage/`: одна таблица сырых собранных документов, одна — итоговых выдач,
одна — прогонов с `meta`. `docker compose` сервис `postgres`, `psycopg`.
Parquet остаётся форматом расчёта; Postgres — то, куда `core.build` и `ingest.live`
пишут результат в конце. Снимает строку «СУБД: PostgreSQL» из ожидаемого стека.
