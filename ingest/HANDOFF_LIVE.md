## Проверка и использование

1. Распаковать в отдельный каталог, выполнить `python verify_manifest.py`.
2. Сопоставить снимок кода с командной веткой. Дополнение зависимостей:
   `ingest/requirements-news.txt` (feedparser); общий pyproject пока не менялся.
   Для live-ветки GPU, torch и модель эмбеддингов не нужны.
3. Использовать data/index и data/features как разные стадии. Не заменять
   meta.json индекса метаданными признаков. SOURCE SHA в FEATURES соответствует
   works.parquet и cand_docs.parquet внутри индекса.
4. После интеграции кода повторный расчёт новостных признаков без сети:

```text
python -m ingest.features --index PACKAGE/data/index --as-of 2026-09 --source-evidence PACKAGE/evidence/reviewed-publishers-checked.json --output NEW_FEATURES_DIR
```

Пути PACKAGE и NEW_FEATURES_DIR заменить своими. Выходной каталог должен быть новым.
Абсолютные пути в сохранённых meta относятся к машине исходного прогона; источники
в пакете определяются относительными путями и SHA, а не существованием этих путей.

Живой сбор нового запроса описан в README_LIVE.md. Ему нужны сеть и настроенный
LLM-провайдер для перевода. Наличие OPENALEX_API_KEY нужно только для точечной
научной истории; ключи и модели в архив не включены. Новых запросов Google News
при подготовке передачи не выполнялось: после ограничения использован офлайн-кэш.
