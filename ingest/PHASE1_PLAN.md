# Фаза 1: источники и живой сбор

Основание: team/PROMPT-konstantin.md и разрешение пользователя работать автономно.

## Решения

K-10: явный справочник нормализованных доменов; точное совпадение или поддомен
по границе точки, наиболее специфичное правило имеет приоритет. Никаких
автоматических trusted по словам university/government в URL. Незнакомые
источники — unknown, тип не выдумывается. URL валидируется до сопоставления;
userinfo, неверные схемы и подмена домена не дают доверенности.
Классификация платформ из брифа не означает проверки каждого их материала.
Датасет206: извлечён из настоящего xlsx; неизвестные явно
оставлены unknown с основанием для последующего ручного разбора.

## Проверки

Приоритет по docs/15-finish-plan.md: приёмка K-12 → исправление качества K-13.
Полные корпуса, новые домены, эмбеддинги и кластеризация сняты окончательно.
K-14 и расширение K-15 не являются блокерами текущего критического пути.
K-13 воспроизводит `algorithms for fault` на трёх новостных заголовках, а фильтр
отвергает prompt engineering/RAG/MoE/LoRA/vector database. Нужен отдельный
механизм извлечения названий с документальными подтверждениями, не увеличение
пула n-грамм и не отключение техно-фильтра.

Каждая стадия: сначала регрессионные тесты, затем реализация, ruff и pytest.
Новые зависимости требуют согласования с владельцем pyproject (Антон).
Никаких изменений core/cards/contracts, корпуса Фазы0 не пересобирать.
Основной репозиторий mranton152/trendradar (origin), форк сохранён как fork.
Критерии300 документов/180сек измерять настоящим прогоном, не считать
синтетические тесты доказательством скорости или полноты.
