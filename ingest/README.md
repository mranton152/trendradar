# Золотой срез OpenAlex (K-01 / K-02)

Запуск из корня репозитория (Python 3.12+, зависимости из pyproject.toml):

```powershell
python -m ingest.harvest --domain artificial-intelligence --years 2015-2026 --sample 5000 --as-of 2026-09-08 --exclude-file data/index/golden/excluded_doc_ids.json
python -X utf8 contracts/validate.py data/index/golden/works.parquet --schema works
python -m pytest ingest -q
python -m ruff check ingest
```

Выход: `data/index/golden/works.parquet` и `manifest.json`.
Команда применяет сохранённые исключения по аудиту URL. Для нового первичного
среза без этих исключений уберите `--exclude-file` и укажите другой `--output`,
чтобы сохранить передаваемый очищенный снапшот.
Концепт разрешается по точному имени: Artificial intelligence → C154945302.
Тип документов — article. Источники URL — DOI либо landing_page_url из OpenAlex;
URL не выдумываются. Abstract восстанавливается из abstract_inverted_index.
Отсутствующий abstract остаётся null. Страны собираются из authorships и institutions.

## Выборка и воспроизводимость

По 417 записей за 2015–2022 и по 416 за 2023–2026. Для каждого года запрашивается
случайная выборка с запасом 100 записей, seed=42, затем берутся первые пригодные
записи. Отказы нормализации перечислены в manifest.json. Если пригодных записей
не хватает, команда завершается с ошибкой и не публикует неполный Parquet.
Размер страницы всегда 100, включая последнюю страницу.

Кэш: `data/cache/golden-openalex/`. Успешный ответ записывается атомарно;
повторный запуск использует уже скачанные страницы. Для офлайн-повтора:

```powershell
python -m ingest.harvest --as-of 2026-09-08 --offline --exclude-file data/index/golden/excluded_doc_ids.json --output data/cache/golden-replay
```

Нужно сохранить исходный кэш: один seed не фиксирует изменяющуюся базу OpenAlex.
Время первого прогона сохраняется рядом с кэшем и повторно используется.
При одинаковых данных и версии pyarrow файл воспроизводится побайтово.
Полный корпус, cursor-пагинация и эмбеддинги относятся к следующим задачам;
этот CLI создаёт только небольшой срез.

Ключ необязателен для небольшого прогона. Если нужен, клиент читает
`OPENALEX_API_KEY` из окружения и передаёт в Authorization; ключ не попадает
в URL, кэш или manifest. Кэш и полные корпуса в git не включаются.

На Windows валидатор запускается с `-X utf8`: его символ ✓ не выводится
в консоль с кодировкой cp1251. Код общего валидатора не изменён.

## Ограничения

- Равномерная по годам выборка нужна для разработки. По ней нельзя оценивать
  частоты полного корпуса или доказывать предсказательную силу детектора.
- 2026 неполный, ограничен параметром `--as-of`.
- Фильтр концепта OpenAlex допускает междисциплинарные работы.
- Отбор пригодных записей исключает документы без проверяемого URL/названия.
- Наличие URL в метаданных не гарантирует доступность издателя из любой сети.
  Фактический объём сетевой проверки указан в quality_report.json.
