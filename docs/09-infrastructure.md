## 2. Основная машина: MacBook M4 Pro

Вся разработка и ML — здесь. Что важно учесть:

### 2.1. Metal не пробрасывается в Docker

Главное ограничение. На macOS контейнеры не видят GPU, поэтому:

```
┌─ хост macOS (нативно) ─────────────────┐
│  Ollama / MLX — LLM и эмбеддинги       │  ← использует Metal
│  тяжёлые ML-прогоны (UMAP, HDBSCAN)    │
└────────────────┬───────────────────────┘
                 │ host.docker.internal
┌────────────────▼───────────────────────┐
│  Docker Compose                        │
│  postgres+pgvector · redis · api ·     │  ← инфраструктура и приложение
│  worker · frontend                     │
└────────────────────────────────────────┘
```

Если запустить эмбеддинги внутри контейнера, они пойдут на CPU в виртуалке —
разница в разы. В конфиге предусмотреть переключатель
`LLM_BACKEND=ollama_host | vllm_container | api`.

### 2.2. Только arm64-образы

Проверить, что все образы имеют arm64-варианты (`pgvector/pgvector`, `redis`,
`node`, `python`). Эмуляция x86 через Rosetta съест производительность.

### 2.3. Память Docker Desktop

Выделяется из общей unified memory. Поднять лимит заранее (рекомендуемо 8–12 ГБ),
иначе Postgres с векторными индексами упрётся в потолок в самый неподходящий момент.

VPS на месяц под демо (4 CPU / 8 ГБ достаточно, если индекс предрассчитан) или
показывать с ноутбука через туннель. Решение — ближе к 25.09, когда будет понятен
реальный размер индекса.

## 4. Git и репозиторий

Репозиторий: `/home/lct-trendradar` на сервере. Публикация на GitHub — по решению
команды; для хакатона почти наверняка понадобится публичный или доступный жюри
репозиторий с **честной историей коммитов** (один коммит «initial commit» в конце
выглядит плохо).

Синхронизация между сервером и маком — через удалённый репозиторий, не через rsync.
