# Стек и обоснование

Принцип отбора: **только то, что переживёт закрытый контур банка**. Никаких
облачных API как обязательной зависимости, всё open-source, всё поднимается
одной командой.

## Бэкенд

| Компонент | Выбор | Почему |
|---|---|---|
| Язык | Python 3.12 | Один язык на ML и API — при команде из 3 человек и 2 неделях это решает |
| API | FastAPI + Pydantic v2 | OpenAPI из коробки — сервис встраивается в Платформу ИИ-аналитики; строгие схемы дисциплинируют выдачу LLM |
| Очередь задач | arq (Redis) | Легче Celery, async-native. Долгий сбор данных уходит в фон |
| Реляционка | PostgreSQL 16 + pgvector | Документы, метрики, эмбеддинги в одном месте. Не тащим отдельную векторную БД ради 10^6 векторов |
| Аналитика рядов | DuckDB + Parquet | Агрегации по годам/странам/организациям на порядок быстрее, чем в Postgres, без отдельного кластера |
| Кэш | Redis | Кэш запросов + брокер очереди |

Сознательно **не берём**: Kafka, Airflow, Kubernetes, отдельный OpenSearch.
На двухнедельном хакатоне это чистые накладные расходы; Postgres FTS + arq
закрывают потребность.

## ML

| Компонент | Выбор | Почему |
|---|---|---|
| Эмбеддинги | `multilingual-e5-large` или `BGE-M3` | Русский + английский в одном пространстве — запрос на русском, корпус на английском. Критично для этого заказчика |
| Кластеризация | UMAP + HDBSCAN (подход BERTopic) | Находит темы без заранее заданного числа кластеров |
| Метки кластеров | c-TF-IDF + LLM-переформулировка | Автоматическое имя темы |
| Ключевые фразы | KeyBERT / YAKE | Кандидаты-термины в дополнение к кластерам |
| Временные ряды | numpy/scipy | OLS, всплески, ускорение — тяжёлая артиллерия не нужна |
| Граф | networkx + Leiden | Со-встречаемость тем, поиск ещё не возникших связей |
| LLM | Qwen2.5 (7–14B) через Ollama, абстракция провайдера | Локально на M4 Pro; провайдер меняется конфигом на GigaChat/YandexGPT в контуре банка |

## Фронтенд

| Компонент | Выбор | Почему |
|---|---|---|
| Каркас | Next.js 15 + TypeScript | Быстрый старт, SSR для скорости первой отрисовки |
| Стили | Tailwind | Скорость на хакатоне |
| Графики | Recharts или visx | Динамика публикаций, доля стран, лаг «публикация → патент» |
| Граф связей | react-force-graph | Карта смежных тем — сильный визуальный аргумент на защите |
| Экспорт | XLSX (SheetJS) + PDF (серверный) | Аналитики банка живут в Excel и PowerPoint, не в вебе |

## Инфраструктура

| Компонент | Выбор |
|---|---|
| Контейнеризация | Docker Compose (multi-arch, обязательно arm64 для M4) |
| Линтеры | ruff + mypy, eslint + prettier |
| Тесты | pytest; отдельный набор на метрики скоринга |
| CI | GitHub Actions: линт + тесты + сборка образов |
| Конфиг | pydantic-settings, `.env`, без секретов в репозитории |

## Ограничения платформы M4 Pro (ARM64)

1. **GPU не виден из контейнеров.** Metal недоступен внутри Docker на macOS.
   Эмбеддинги и LLM — нативным процессом на хосте, приложение ходит к нему по HTTP.
2. **Только arm64-образы.** Проверить `pgvector`, `ollama`; при эмуляции x86
   производительность падает в разы.
3. **Память Docker Desktop** выделяется из общей unified memory — заранее
   поднять лимит, иначе Postgres и индексация будут упираться в потолок.

## Что осознанно оставляем на потом

Fine-tuning собственной модели, полноценный knowledge graph, стриминг обновлений
в реальном времени, мультитенантность. Всё это — материал для слайда «развитие
продукта», а не для двух недель разработки.
