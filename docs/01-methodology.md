# Методология детекции зарождающихся трендов

Это ядро решения. Заказчик отдельно требует «представить методологию определения
зарождающегося тренда», поэтому она должна быть формальной, воспроизводимой и
объяснимой аналитику без ML-образования.

## 1. Определение: что считаем зарождающимся трендом

Опираемся на устоявшуюся рамку Rotolo, Hicks & Martin (2015), «What is an emerging
technology?» — пять признаков. Наши метрики — их прямая операционализация:

| Признак по Rotolo | Наша метрика | Как считается |
|---|---|---|
| Radical novelty | **N** — новизна | Год взлёта (takeoff), см. §3.1 |
| Relatively fast growth | **G** — рост | Наклон log-частоты за окно |
| Coherence | **C** — связность | Плотность кластера в эмбеддинг-пространстве |
| Prominent impact | **I** — потенциал влияния | Ранняя цитируемость + патентная активность |
| Uncertainty & ambiguity | **U** — неопределённость | Не входит в скор, показывается как флаг доверия |

Плюс две метрики от себя, важные именно для банка:

| Метрика | Смысл |
|---|---|
| **D** — распространение | Растёт ли число независимых организаций и стран |
| **T** — трансляция в практику | Лаг «публикация → патент → продукт», признак коммерциализации |

Ключевое отличие зарождающегося тренда от популярного: **зарождающийся ещё не
стал мейнстримом**. Поэтому высокая абсолютная частота — это не плюс, а минус
(см. штраф за зрелость в §3.6).

## 2. Схема расчёта

```
запрос пользователя ("технологии в ИИ")
        │
        ├─► нормализация домена ──► набор фильтров по источникам
        │
        ├─► ГЕНЕРАЦИЯ КАНДИДАТОВ  (§4) ──► ~10^3-10^4 терминов/тем
        │
        ├─► ВРЕМЕННЫЕ РЯДЫ        ──► точная годовая динамика по каждому кандидату
        │
        ├─► СТРУКТУРНЫЕ ФИЛЬТРЫ   (§5) ──► отсев артефактов и мейнстрима
        │
        ├─► EMERGENCE SCORE       (§3) ──► ранжирование
        │
        ├─► ДЕДУПЛИКАЦИЯ + РАЗНООБРАЗИЕ (§6) ──► ТОП-15 непересекающихся тем
        │
        └─► ДОКАЗАТЕЛЬНАЯ ГЕНЕРАЦИЯ (§7) ──► мотивация, кейс, источник
```

## 3. Компоненты Emergence Score

Дано: для термина/темы `t` годовой ряд числа документов `c[y]`.

### 3.1. N — новизна: год взлёта, а не первого упоминания

Наивный «первый год упоминания» **не работает**, и это проверено на данных: в
корпусе из 34 млн работ почти у любого термина найдутся единичные срабатывания
20-летней давности (омонимы, ошибки метаданных, OCR). В нашем спайке это отсеяло
100 из 106 кандидатов как «слишком старые».

Считаем две величины:

- `first_mention` — первый год, где `c[y] >= 5` (показываем пользователю, как
  требует ТЗ);
- `takeoff` — первый год, где `c[y] >= max(10, 0.10 * peak)`, т.е. выход на 10%
  собственного пика (используем в скоринге).

```
age = cutoff_year − takeoff
N   = 1 − age / MAX_AGE,   MAX_AGE = 8 лет
```

### 3.2. Нормировка частоты: peer-нормировка

Абсолютные счётчики нельзя сравнивать между годами — наука растёт сама по себе.
Но нормировка на весь корпус домена даёт **систематическую ошибку**: OpenAlex
индексирует метаданные быстрее, чем абстракты, поэтому поиск по тексту отстаёт от
общего счётчика работ, и последний год ложно проседает. Мы наступили на это в
спайке: у всех терминов подряд 2026 год показывал падение.

Решение — **peer-нормировка**: знаменатель считается тем же способом, что и
числитель (сумма активности пула кандидатов за год):

```
f[y] = c[y] / Σ_t c_t[y] × 10^6
```

Годовой перекос индексации сокращается, поскольку присутствует и в числителе,
и в знаменателе.

### 3.3. G — рост

Наклон OLS по логарифму частоты за окно `W = 5` лет:

```
G = slope( y → ln(f[y] + 1) )
```

Логарифм, потому что нас интересует относительный (экспоненциальный) рост.

### 3.4. A — ускорение

Вторая производная: разница наклонов второй и первой половины окна.

```
A = slope(вторая половина) − slope(первая половина)
```

Именно ускорение отличает зарождающийся тренд от равномерно растущей области.

### 3.5. B — всплеск (burst)

Упрощённый Kleinberg (2002): во сколько раз последний год превысил ожидание по
предыдущей базовой линии.

```
B = (f[last] + ε) / (mean(f[:last]) + ε)
```

### 3.6. Штраф за зрелость

```
ES = Σ w_i · rank_i × (1 − 0.5 · rank(maturity))
```

где `maturity = f[last]` — абсолютная относительная частота. Тема, которая уже
занимает заметную долю домена, — это мейнстрим, а не слабый сигнал.

### 3.7. Приведение компонент к одной шкале

Все компоненты переводятся в **перцентильный ранг** внутри пула кандидатов.
Причина: распределения тяжёлохвостые, z-score и min-max разъезжаются от одного
выброса. Перцентиль устойчив и интерпретируем («в топ-10% по ускорению»).

Текущие веса (подлежат калибровке на бэктесте, см. §8):

```
N 0.20 | G 0.32 | A 0.23 | B 0.15 | D 0.10
```

## 4. Генерация кандидатов — самое узкое место

**Главный вывод спайка: скоринг уже работает, а вот кандидаты плохие.**

Бэктест на срезе 2021 дал 13 из 15 растущих терминов (до x3.0), но это были
*уже горячие* темы — GAN, CNN, transfer learning. Настоящие слабые сигналы того
момента (transformer, diffusion model, self-supervised) не попали в список.

Причина: n-граммы из заголовков случайной выборки — это частотный отбор. При
пороге «термин встречается минимум в 8 заголовках из 2500» мы по построению
находим только то, что уже популярно. Слабый сигнал — это 10–100 работ в год на
домен в миллионы работ, то есть длинный хвост.

Четыре направления, которые нужно совместить:

1. **Полный корпус вместо выборки.** Снапшот OpenAlex / arXiv целиком, а не
   `sample=N`. Тогда порог кандидата можно опустить до десятков документов.
2. **Опережающие источники.** Препринты дают фору (измерено: медиана 1 год),
   репозитории и модели на HuggingFace — ещё раньше. Журналы использовать как
   подтверждающий, запаздывающий сигнал.
3. **Тематические кластеры, а не только термины.** Эмбеддинги (E5/BGE-M3) →
   UMAP → HDBSCAN, метки кластеров через c-TF-IDF. Тренд часто не имеет
   устоявшегося названия — по определению, он же зарождающийся.
4. **Технологический фильтр сущностей.** Отсекать нетехнологические фразы
   («covid-19 pandemic» занял 1-е место в бэктесте) и boilerplate. Вариант —
   NER по технологиям + проверка по техно-лексикону.

Отдельная задача — **омонимия**, и она решена наполовину.

Замер 09.09.2026 по живым рядам OpenAlex показал, что случая два, и они разные.

**Случай первый: старая тема заглохла.** Между жизнями термина лежит провал
в десять и более лет. Ловится по форме ряда — `core/homonym.py` режет ряд на
сегменты активности и считает новизну по последнему.

**Случай второй: старый смысл публикуется параллельно.** Разрыва нет вообще:

```
state space model   2000: 96 … 2024: 534, 2025: 1166, 2026: 1349
diffusion model     2000: 30 … 2022: 209, 2023: 502,  2024: 1452
```

Теория управления и физика диффузии дают ровный фон, Mamba и генеративные
модели — скачок относительно этого фона. Ловится изломом собственного тренда:
`core/breakout.py` берёт медианный уровень термина за пять лет до окна поиска
и ищет первый год, где активность превысила этот уровень в 2,5 раза.

Часть омонимии снимается сама фильтром по домену: «diffusion model» по всему
OpenAlex взлетает в 2002, а внутри концепта «Artificial intelligence» — в 2023.
Но не вся: «state space model» и внутри домена ИИ давал 2005, потому что теория
управления в OpenAlex тоже размечена как ИИ.

Результат на живых рядах:

| Термин | Взлёт до починки | После | Что было бы |
|---|---|---|---|
| diffusion model | 2002 | 2023 | отсеян как «старше 8 лет» |
| state space model | 2005 | 2025 | отсеян как «старше 8 лет» |
| vision transformer | 2022 | 2022 | без изменений |
| neural radiance field | 2023 | 2023 | без изменений |

Оба починенных термина стоят в нашем эталонном списке — то есть до этой правки
метод проваливал собственную проверку.

Обе эвристики работают по форме ряда, а не по смыслу. Настоящее разрешение
требует эмбеддингов контекста; когда появятся кластеры, излом и сегменты станут
подстраховкой. Пока подозрение на тёзку понижает уверенность до `medium`:
выдавать результат эвристики за высокую точность мы не имеем права.

## 5. Структурные фильтры (антифрод сигналов)

Реальные данные грязные. Эти отсечения найдены эмпирически — каждое ловило
конкретный мусор в наших прогонах:

| Фильтр | Порог | Что ловит |
|---|---|---|
| Возраст | takeoff не старше 8 лет | Давно известные темы |
| Объём доказательств | ≥ 20 документов в окне | Статистический шум |
| Число стран | ≥ 5 | Тема одной лаборатории — ещё не тренд |
| Активных лет | ≥ 3 | Всплеск одного года |
| Доля последнего года | ≤ 80% | **Массовая заливка метаданных** |
| Зрелость | не верхний дециль | Мейнстрим |

Пример работы: без этих фильтров первое место в ТОП-15 по ИИ занимал термин
`lynching tree` — 1314 «публикаций» 2026 года, **0 стран**, ноль в предыдущие
годы. Классическая пакетная заливка записей, а не тренд.

## 6. Дедупликация и разнообразие

Две подзадачи:

- **Варианты одного термина** («explainable machine» / «explainable machine
  learning»): схлопывание по пересечению токенов (Жаккар ≥ 0.6) и вложенности,
  побеждает вариант с большим ES, остальные становятся алиасами. В проде —
  канонизация по эмбеддингам, чтобы ловить и синонимы.
- **Разнообразие ТОП-15**: без него список вырождается в 15 оттенков одной темы.
  Отбор через MMR (maximal marginal relevance) по эмбеддингам: максимизируем ES
  при штрафе за близость к уже отобранным.

## 7. Доказательная генерация текста

Требуемые ТЗ поля (мотивация, кейс-пример) генерируются LLM, но **только по
найденным документам** (RAG), со строгими ограничениями:

- вход — top-k документов кластера, патенты, упоминания компаний;
- выход — строгая JSON-схема, без свободного текста;
- каждое утверждение несёт `doc_id` источника;
- утверждения без источника отбрасываются на постобработке;
- метрика качества — **доля утверждений с подтверждённым источником** (целимся в 100%).

LLM здесь не «придумывает тренды», а формулирует то, что уже найдено метриками.
Это принципиально: числа считает статистика, текст пишет модель.

## 8. Валидация

Без валидации методология — набор коэффициентов. План проверки:

### 8.1. Временной бэктест
Считаем на срезе `cutoff = 2021`, оцениваем по данным 2022–2026.

- **Precision@15** — доля трендов, реально выросших после среза
  (текущий результат спайка: 13/15, но с оговоркой из §4);
- **Lead time** — за сколько лет до пика тренд был обнаружен;
- **Recall по эталону** — список технологий, которые заведомо выстрелили
  (transformer, diffusion models, LLM, RAG, SSM/Mamba, LoRA, vector DB,
  vision-language models), собирается вручную заранее.

### 8.2. Сравнение с базовыми методами
Обязательно, иначе непонятно, что даёт наша модель:

| Baseline | Смысл |
|---|---|
| Топ по абсолютному приросту публикаций | «наивный рост» |
| Топ по CAGR | «наивный процент» |
| Только LLM без данных | «а зачем вам метрики» |

### 8.3. Абляция
Отключаем компоненты по одной и смотрим падение Precision@15 — показывает вклад
каждой метрики. Хорошо смотрится на слайде.

### 8.4. Экспертная оценка
5–7 трендов на слепую оценку человеку, шкала «зарождающийся / уже известный /
не тренд». Согласованность с моделью — отдельная цифра для питча.

## 9. Открытые методологические вопросы

- Как формально задать порог «уже мейнстрим» — сейчас перцентиль, хочется
  привязку к абсолютной доле рынка публикаций.
- Как учитывать переименование технологии во времени (тренд живёт, название
  меняется) — вероятно, отслеживание кластеров, а не строк.
- Множитель излома (2,5) подобран по двум измеренным рядам. Его надо
  откалибровать на бэктесте: слишком низкий начнёт вытаскивать наверх ровно
  растущий мейнстрим, слишком высокий пропустит вторую жизнь термина.
- **Как показывать год первого упоминания у термина со второй жизнью.**
  На карточке `mixture of experts` сейчас написано «зарождение, взлёт 2024,
  первое упоминание 1994» — и это правда: идея из 1991 года, а нынешняя волна
  началась в 2024. Но выглядит как противоречие, и жюри на нём споткнётся.
  Нужна либо другая подпись («первое упоминание термина» против «начало
  нынешней волны»), либо явная пометка о второй жизни. Данные для этого уже
  есть: `homonym_suspected` считается, просто не выведен в контракт.
- Как взвешивать источники разной надёжности (arXiv vs Nature vs корпоративный
  блог) — нужна модель доверия к источнику.
- Нужен ли отдельный детектор «затухающих» трендов — заказчику может быть важно
  не только куда входить, но и откуда выходить.
