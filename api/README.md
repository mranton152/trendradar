# API: этап M-01

Запуск из корня проекта (Python 3.12, зависимости из pyproject.toml):

```powershell
uv sync --frozen
uv run uvicorn api.main:app --host 127.0.0.1 --port 8000
```

Проверка: `GET http://127.0.0.1:8000/api/v1/health`.

```json
{"status":"ok","indexed_domains":[],"offline_mode":true}
```

`status: ok` означает, что API работает. Пустой `indexed_domains` означает,
что готовых индексов ещё нет; при старте в журнал выводится понятное предупреждение.
Папка становится доступным доменом после появления читаемого `trends.parquet`.
Один `works.parquet` в golden пока не делает этот домен готовым для выдачи трендов.

`Store` загружает Parquet через DuckDB один раз при запуске, закрывает соединение
и обслуживает запросы из памяти без сети и повторного чтения файлов. После
обновления индекса API нужно перезапустить. Каждый процесс API держит свой снимок.

- `domains()` — имена папок с загруженными трендами.
- `trends(domain, as_of, top=15)` — срез года, сортировка по rank и ограничение числа.
- `trend(trend_id)` — точный поиск во всех загруженных доменах.
- `works(domain, doc_ids)` — документы в порядке запроса, без повторов.

Документы читаются из `data/corpus/{domain}/works.parquet`, а при его отсутствии —
из `data/index/{domain}/works.parquet`. Отсутствующий корпус допустим: источники
вернутся пустым списком. Повреждённый индекс домена пропускается с предупреждением.
Пути проверяются при загрузке; HTTP-ввод не используется для открытия файлов.

Для тестов и нестандартного расположения данных есть `create_app(index_root)`.
Снимок хранится в `app.state.store`; `api.main.get_store(request)` даёт к нему
доступ обработчикам и может использоваться в следующих маршрутах.
Сигнатура `works(domain, doc_ids)` следует примеру реализации M-01 и вызовам M-02.

```powershell
uv run pytest api/ -q
uv run ruff check api/
```

В M-01 опубликован только health. Эндпойнты выдачи трендов относятся к M-02.
